## 问题对照

### 问题1 · lint 17 条警告（R8）

- **根因**：未使用变量/导入、显式 any、console 调用等散落在 8 个文件（BattleScene3D 死状态、BattleReview 冗余导入、测试文件未用变量等）。
- **修复**：逐项清除死代码与冗余导入；`eslint.config.js` 调整 no-console 仅允许 warn/error；修复后 111 用例保持全绿无回归。

### 问题2 · 概率判定不可重现（R1）

- **根因**：`penetration.ts`、`chainReactions.ts`、`HitSimulator.ts`、`battleStore.ts` 全链路直接调用 `Math.random()`，同一发命中无法复盘，回归测试无法写断言。
- **修复**：新建 `lib/rng.ts`（mulberry32 可播种 PRNG），`createRng(seed)` 注入式替换全链路 10+ 处随机调用；store 持有 `rngSeed` 自增、每次开火记录 `hit.seed`；新增 `rng.test.ts` 6 个用例（同 seed 深度相等 / 异 seed 破片锥不同）。

### 问题3 · 后端零测试 + mapHit 隐式 any（R3）

- **根因**：backend 无任何测试文件，`mapHit(h)` 参数为隐式 any，Zod 校验与 Prisma 写库之间的类型契约靠人肉保证。
- **修复**：引入 vitest 2.1.1 + supertest，`index.ts` 导出 app 并改为 `process.env.VITEST` 条件监听；独立 `test.db`（测试前 `prisma db push` 重建）；27 个用例覆盖 CRUD 正路径/非法入参/分页边界；`mapHit` 改为 `z.infer<typeof HitSchema>` 强类型。
- **附带发现真缺陷**：`UpdateBattleSchema` 允许 `notes` 字段但 Prisma schema 无此列，PATCH notes 必然 500 —— 已加列 `notes String @default("")` 修复。

### 问题4 · 双数据源静默分叉（R2）

- **根因**：`client.ts` API 失败时静默回退 localStorage，UI 无任何标识，用户无法分辨记录来自服务器还是浏览器本地，数据可信度存疑。
- **修复**：`BattleDTO` 增加运行时标记 `source?: 'api' | 'local'`（不落库，lsWrite 前剥离）；机库页面检测本地来源记录时显示黄色「离线模式」横幅 + 卡片「本地」徽标。

### 问题5 · 战斗记录无分页（R4）

- **根因**：`GET /api/battles` 全量返回，记录增长后前端一次性渲染，性能与内存无保障。
- **修复**：后端支持 `?page=&pageSize=`（≤200），返回 `{items,total,page,pageSize}`，无参保持数组向后兼容；前端 `listBattlesPaged` + 机库「加载更多（x/total）」按钮；本地回退路径同样支持切片分页；4 个分页用例覆盖正路径/越界/非法参数回退。

### 问题6 · CI 质量门半缺

- **根因**：CI 只跑 lint + 前端 build，后端零测试、无覆盖率约束、`backend/.env` 被 git 跟踪（密钥泄露隐患）。
- **修复**：CI 新增 3 步——`backend/.env` 未跟踪检查（git ls-files 反向校验）、前端 `test --coverage` 覆盖率门槛（vitest.config.ts：lib/ lines/statements/functions ≥80、branches ≥70）、后端 `npm run test`；`.env` 取消跟踪并新增 `.env.example` 模板。
