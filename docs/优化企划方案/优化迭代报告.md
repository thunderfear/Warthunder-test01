## 第二期：扩展能力突破（预计 2–4 周，结构性改动）

**目标：从"一辆 T-72B3 的演示"升级为"可配置多载具平台"。**

| #   | 任务                  | 对应风险 | 关键做法                                                                                                                                                                                               |
| --- | --------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 2.1 | 载具注册表重构        | R5       | `data/` 新增 `vehicles/index.ts` 注册表（id → 2D 分区 + 3D 碰撞体 + VehicleConfig）；`lib/` 层改为接收载具参数而非 import 单例 `VEHICLE`；`battleStore` 的 `DEFAULT_VEHICLE_CONFIG` 移入各载具数据文件 |
| 2.2 | 新增 2–3 辆载具       | R5       | 借助 2.1 的注册表，新增载具只需加一个数据文件（建议：一辆脆皮轻型车 + 一辆重甲车，拉开穿透判定差异）                                                                                                   |
| 2.3 | 概率/伤害系数表数据化 | R7       | `chainReactions.ts` 的 baseRate / ammoMultiplier 表与 store 层魔法数字（0.5kg TNT、1.5m、0.3 爆炸概率）抽取为 `data/balance.ts`，策划可调                                                              |
| 2.4 | GLB 精细模型导入      | 遗留①    | GLTFLoader + Draco 压缩；碰撞体仍用现有简化分区（视觉与碰撞分离，正交演进）                                                                                                                            |
| 2.5 | 回放时间轴 UI         | 遗留④    | 播放/暂停/逐帧/进度条/速度档位，复用现有 replayIndex/replaySpeed 状态                                                                                                                                  |
| 2.6 | 命中分析报告导出      | —        | 单场战斗导出 PDF/CSV（QA 场景直接可用作测试附件）                                                                                                                                                      |

**验收标准：**

- 新增一辆载具的全流程（数据 → 3D 渲染 → 命中判定 → 测试）不改 `lib/` 任何一行代码（以 PR diff 证明）
- ≥ 3 辆载具可选、可切换，各自测试矩阵（5 弹种 × 关键分区）全绿
- 平衡系数改动只发生在 `data/balance.ts`
- GLB 模型首屏加载 ≤ 3s（本地），OrbitControls 帧率 ≥ 50fps（dev 工具实测）
- 回放时间轴可暂停在任意帧并显示该帧命中数据

**目标：原型 → 可长期演进的产品形态。**

## 执行建议

1. **每期开工前先跑基线**：`npm test` + `npm run lint` 留档，期尾对比（本项目已有 auto-kill.ps1 与 start.bat，验证流程沿用即可）。
2. **遵守 AGENTS.md 硬性禁令**：尤其禁令 2/3（vite.config.js 事实源、禁止本地 build 覆盖）贯穿所有期次；第一期任务 1.6 清理 lint 时不得触碰 vite 配置文件。
3. **每期结束更新本报告状态**，并将期次产出截图归档（沿用现有 verify-*.png 命名规范）。
4. 若时间有限，**第一期优先级最高且不可分割**——它决定了后续所有改动的安全性。
